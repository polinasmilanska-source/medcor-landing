# Медкор Зюйд — навчальний лендінг

Статичний україномовний прототип для навчального проєкту. **Не є офіційним сайтом медичного центру.** Не використовуйте для реальних пацієнтів або передавання медичних даних.

## Структура

- `index.html` — єдина сторінка; варіанти заголовка A/B доступні через `?variant=a` і `?variant=b`.
- `assets/styles.css` — локальні адаптивні стилі.
- `assets/app.js` — варіант заголовка, згода на аналітику, безпечні події.
- `assets/config.js` — налаштування GA4 і Microsoft Clarity; за замовчуванням вимкнені.
- `assets/diagnostics.svg` — авторська умовна ілюстрація.

## Локальний перегляд

Запустіть у цій папці:

```bash
python -m http.server 8000
```

Відкрийте `http://localhost:8000`. Для варіанта B: `http://localhost:8000/?variant=b`.

## Публікація через GitHub Pages

1. Увійдіть у свій GitHub-акаунт і створіть **Public repository**, наприклад `medcor-landing`.
2. Завантажте **вміст цієї папки** до кореня репозиторію. Важливо: `index.html` має бути в корені, а `assets/` — поруч.
3. Відкрийте **Settings → Pages**.
4. У розділі Build and deployment виберіть **Deploy from a branch**, branch `main`, folder `/(root)`, натисніть Save.
5. Дочекайтеся завершення публікації. Типова адреса: `https://ВАШ-ЛОГІН.github.io/medcor-landing/`. Фактичну адресу GitHub покаже в Settings → Pages.

Не можна визначити фактичну адресу сайту до створення репозиторію та публікації.

## Налаштування GA4 та Microsoft Clarity

Аналітика за замовчуванням **вимкнена**. Не створюйте/не використовуйте трекери для реальних пацієнтів на цій навчальній сторінці.

1. Створіть GA4 property і Web data stream; скопіюйте Measurement ID формату `G-XXXXXXXXXX`.
2. Створіть Microsoft Clarity project; скопіюйте Project ID.
3. У `assets/config.js` внесіть власні ID та змініть `enabled: false` на `enabled: true`.
4. Переконайтеся, що тестування погоджене, учасників поінформовано, а налаштування маскування Clarity перевірено. Опублікуйте зміну.
5. Перевірте сценарії «Дозволити» і «Відмовитися» у браузері. Для GA4 перевірте Realtime/DebugView; для Clarity — чи надходить тестова сесія лише після згоди.

Події GA4, які надсилаються після згоди: `page_view`, `experiment_view`, `contact_open`. Параметри `variant` та `placement` можна зареєструвати як custom dimensions у GA4. URL-параметри та фрагменти не передаються в `page_location`.

**Увага:** якщо IDs не заповнені, навіть після згоди жоден трекер не завантажиться. Не вставляйте до аналітики ПІБ, телефони відвідувачів, діагнози, результати чи інші чутливі дані. Згода не робить передавання медичних даних припустимим. Clarity може аналізувати вміст сторінки; не використовуйте його для спостереження за реальними пацієнтами.

## Навчальний A/B-тест

- A: `/?variant=a` — «Діагностика в Одесі. Зрозумілий шлях до запису».
- B: `/?variant=b` — «Потрібне обстеження в Одесі? Дізнайтеся, як записатися».

Інші елементи однакові. Автоматичного розподілу немає: розподіліть погоджених тестувальників випадково 1:1 і дайте кожному лише відповідне посилання. Збирайте дані лише за наявності згоди. Не оголошуйте переможця за малої вибірки.

## Важливі обмеження

- У сторінці збережено `noindex, nofollow`, бо це неофіційний навчальний прототип.
- Телефони та зовнішні посилання наведено за матеріалами навчального звіту; перед публічним використанням перевірте актуальність.
- Це не офіційна сторінка, не медична консультація й не форма запису.
- Адреса GitHub Pages, GA4 Measurement ID і Clarity Project ID не створюються автоматично цим пакетом — вони належать вашому акаунту.
